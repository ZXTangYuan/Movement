## v0.5.3 — 相比 v0.5.2（箭头渲染修复 / 加速度与刹车曲线 / 上台阶顿挫）

> 需求 m02395 三条：① 速度箭头全渲染成竖直的、而且没颜色；② 输入最大加速度 10 m/s² 偏小，
> 且希望「停下时先给最大制动、再降到滑动摩擦」；③ 上台阶有顿挫感。

#### ① 箭头渲染：两个真 bug + 配色重排

| bug | 根因 | 修法 |
|---|---|---|
| **箭头全变竖直** | `Transform` 用 `rot.Scaled(s)`。Godot 的 `Basis::scale()` 是**按行**缩放（`rows[i] *= s[i]`）= `diag(s)·rot`，即**全局轴**缩放。对指向 +Z 的箭头，局部 Y（长度轴）被乘上全局 Z 的缩放系数（= `radius`，只有 1~5 cm）⇒ 箭杆被压成薄片，看起来只剩一条竖线 | 改成 `rot * Basis.FromScale(s)`（后乘 = **局部轴**缩放） |
| **七种颜色全变一种蓝** | `CollectMeshes` 递归收集玩家网格时**把渲染器自己也收进去了**，开 ghost 时把所有箭头的 `MaterialOverride` 换成同一份半透明蓝 | `CollectMeshes` 首行 `if (node == this) return;` |

`Basis` 语义用 headless 脚本实测确认（`.re-apex/work/basis_check.gd`）：

| 方向 | 后乘（正确）长度轴长度 | `Scaled`（错误）长度轴长度 |
|---|---|---|
| forward(-Z) | 0.5000 | **0.0300** |
| right(+X) | 0.5000 | **0.0300** |
| diag | 0.5000 | 0.2551（方向也歪了） |

配色按色相拉满重排（重力红 / 摩擦蓝 / 输入绿 / 冲量黄 / 碰撞紫 / 合计青 / 速度白），
速度箭头单独加粗（第三人称正后方看前向速度时会被透视压成点），标签加黑描边，
HUD 图例加半透明黑底。截图新增 `shot_dbg_walk_diag`（W+D 斜向跑），
用来证明速度箭头确实是三维矢量。

> 试过并**放弃**：几何黑色描边（外层放大 1.9 倍黑圆锥）。箭头是 Unshaded + NoDepthTest
> 的不透明材质，外层黑壳会把内层彩色整个盖住，实测截图里箭头变成黑团。

#### ② 驱动加速度 10 → 14 m/s²，刹车曲线改方向

**能不能改 / 会不会破坏物理自洽**：能改。`GroundAccel` 是**设计目标**（肌肉能给出的推力），
不是物理常数。真正与物理耦合的只有抓地条件 `μs·g·cosθ ≥ 驱动加速度`，所以
`GroundStaticFrictionCoefficient` 从 1.35 同步提到 **1.9**（推导：30° 坡 `μs ≥ 14/(9.80665×0.866) = 1.65`，留 15% 余量）。

| 量 | 改前 | 改后 |
|---|---|---|
| 冲刺到顶速时间 | 0.66 s | **0.47 s** |
| 平地最大静摩擦加速度 | 13.24 m/s² | **18.63 m/s²** |
| 平地滑动摩擦（μk=0.7） | 6.865 m/s² | 6.865 m/s²（不变） |
| 45° 坡抓地 | 抓得住 | 开始轻微打滑（μs·g·cos45° = 13.2 < 14） |

**刹车曲线**原来方向是反的（从 0 长到 `μs·g`，弱→强）。现在按需求「先最大制动、再降到滑动摩擦」：

```
a(t) = μk·g·cosθ + (a₀ − μk·g·cosθ)·(1 − min(1, t/T))
a₀   = min(μs·g·cosθ, GroundAccel)        // 平地 14 m/s²
T    = BrakeRampTime = 0.25 s
```

实测（v = 6.6 m/s 松手，`FrictionTest` ⑤/⑤b）：第 1 tick 掉 **0.2254 m/s**（= 14·dt）、
中段 0.1778、抱死后 **0.1144 m/s/tick**（= μk·g·dt，偏差 −0.00%）。
理由：人主动停下时**先用力蹬地**（静摩擦做负功），速度降下来脚才逐渐锁死成滑动；
反过来（先弱后强）会让「刚松手那一下」几乎不掉速，感觉像刹不住。

#### ③ 上台阶顿挫：两个独立病因

| # | 病因 | 量化 | 修法 |
|---|---|---|---|
| **A** | `TryStepUp` 一帧把人抬到台面（0.20 m 台阶 = 单帧 0.2010 m ≈ 12 m/s），相机每渲染帧直读 `_core.Position` ⇒ 一帧硬跳 | `max\|Δ²p\| = 0.2010`，每级台阶一次孤立尖峰 | 眼位**上升速率**限速（`StairEyeSmoothSpeed = 4 m/s`，累积额度、按 tick 发放）：单帧竖直位移 **0.1399 → 0.0667 m** |
| **B** | `ApplyStepTilt` 按 `cosθ` 缩水平、差额塞进竖直；但竖直分量下一 tick 就被贴地吸附整段抹掉 ⇒ **水平速度净掉 cosθ 且不可恢复** | 走 4.407→3.866（87.7%）、跑 6.604→4.543（68.8%）、0.25 m 台阶跑只剩 52.5%；0.5 m 踏面每 4~5 tick 一级而补回满速要 6 tick ⇒ 掉速累积到 72% | 水平分量**原样保留**，竖直照旧叠加：水平速度 **100%**、`ticks<90%顶速` 31→0 |

眼位平滑的三条边界（都是刻意这样设计的）：

* **向下 / 腾空不限速** —— 走下台阶、坠落、落地永远跟手；
* **下坡不触发** —— 30° 斜坡冲刺正常抬升 6.604×tan30° = 3.81 m/s < 4 m/s，零滞后；
* **连续爬楼不累积滞后** —— 0.20 m / 0.5 m 踏面 @ 6.604 m/s 的平均抬升是 2.64 m/s < 4 m/s。

另外补了一条回归断言（`ClimbTest` ⑲）：**水平速度零损失**（改前只能断言「|v| 大小不变」，
而 |v| 不变恰恰掩盖了水平分量被 cosθ 吃掉、竖直分量被吸附吃掉这件事）。

## v0.5.2 — 相比 v0.5.1（摩擦重做 / 攀爬翻越平滑 / 调试器性能 / 菜单出屏）

#### ① 摩擦重做：静摩擦做正功 + 冰面打滑 + 空中只靠惯性（需求 m01928 第 4 点）

**旧模型的问题**：不管人是不是在打滑，每 tick 都按库仑滑动摩擦往速度反方向扣一份
`μk·g·cosθ·dt`。这等于假设"人一直在滑动"，而实际上**走路时脚是钉在地上的**：
静摩擦做的是**正功**，方向沿**输入方向**，不是沿速度反方向。

**新模型**（`ApexMovementCore.ApplyGroundFrictionAndDrive`）分三种工况：

| 工况 | 物理 | 实现 |
|---|---|---|
| 有输入 + 未超速 | 静摩擦做正功，方向 = 输入方向 | `a_drive = accel·|input| + g·sinθ·(输入·下坡)`，上限 `μs·g·cosθ` |
| 有输入 + 已超上限 | 转向时静摩擦把速度压回上限 | 只限制**本 tick 加进去的增量**，绝不回削已合法的速度 |
| 无输入 | 刹车：静摩擦缓慢长到最大 → 抱死成滑动摩擦 | `μ_eff = μs·min(1,t/T_ramp)`，之后 `μk` |

**抓地判定**（冰面效果的来源）：
`grip = min(1, μs·g·cosθ / 需要的推进加速度)`。抓不住时推进力按 `grip` 衰减，
并且叠加一份**随滑移速度增大**的耗散 `μk·g·cosθ·(1−grip)·(1+v/vRef)` ——
于是打滑地面有一个**稳定终端速度**，既"难以行走"又不会把玩家永久卡住。

| 地面 | μk | grip | 实测（狂按 W 5 s） |
|---|---|---|---|
| 默认（干硬地） | 0.70 | 1.00 | 4.41 m/s（正常走速，**逐位不变**） |
| 湿滑 | 0.30 | 0.57 | 3.5 m/s（明显打滑、转不动） |
| 冰面 | 0.05 | 0.095 | **0.97 m/s**（能挪，但挪不快） |

**静/动摩擦系数**：`GroundStaticFrictionCoefficient = 1.35`（默认）、
`GroundKineticFrictionCoefficient = GroundFrictionCoefficient = 0.7`。
1.35 不是"看起来像"，是被设计加速度倒逼的：要保证正常地面完全抓地，必须
`μs ≥ accel/g = 10/9.80665 = 1.02`；取 1.35 留 14% 余量（45° 陡坡上开始轻微打滑）。

**刹车曲线**（需求「先降低轮胎滚动速度，最后抱死刹车」）：

| | 第一 tick | 斜坡中段 | 抱死后 |
|---|---|---|---|
| 减速量 | 0.0368 m/s | 0.1103 m/s | **0.1144 m/s = μk·g·dt**（与速度无关） |

#### ② 体重：BMI × 身高²（需求 m01928 第 4 点）

`BodyBmi = 21.7`（正常区间 18.5–24.9 的中位数）、`BodyMass = 21.7 × 1.9² = **78.337 kg**`。

> ⚠ **诚实的物理提醒**：在纯移动系统里，质量在摩擦加速度里**约掉了**
> （`a = μN/m = μg`）—— 所以体重**不改变**走跑滑的加减速曲线（FrictionTest ⑦
> 用 40 kg 与 120 kg 实测同一个 6.8647 m/s²）。
> 它真正起作用的地方是**力**：法向力 `N = mg = 768.2 N`、最大静摩擦 `Fs = μs·N = 1037.1 N`、
> 滑动摩擦 `Fk = μk·N = 537.8 N`（HUD 图例里实时显示），以及未来木筏/刚体的冲量传递
> （`Δv = J/m`）。

#### ③ 滑铲输入：W 无效 / A-D 微转向 / S 制动（需求 m01928 第 4 点）

滑铲时脚下是**滑动**，摩擦只沿运动反方向，没有任何"沿输入方向的推进会由静摩擦提供"
的机制 —— 所以 W 无处着力。现在只保留**横向**（垂直滑行方向）微调：

- W：完全无效（实测与不按**逐位相同**）。
- A/D：0.4 秒转 3.0°，且**不加速**（转向后把速度投影回原大小）。
- S：μ 乘 `SlideReverseInputPenalty`，12.55 → 7.25 m/s（不按是 10.78）。

#### ④ 空中输入：只微调方向，不能加能量（需求 m01928 第 4 点）

旧版是 Source 谱系的 air-strafe（`AirAccel=10` + `AirWishSpeed=1.524`），
实测能把 6.6 加到 7.95 m/s（+20%）。现在两道闸：

1. 加速度改用 `AirControlAccel = 1.2`（原来的 12%）；
2. **硬上限**：水平速度 ≤ 离地速度 + `AirSteerSpeedAllowance(0.5)`。

> 这里踩过一个坑：上限基准必须**在进入空中那一帧刷新**（蹬墙跳、松手掉、翻越收尾
> 都不经过跳跃）。否则蹬墙跳的 4.2 m/s 会被上一次落地时的旧基准硬拽到 0.67 m/s
> —— 由 ClimbTest ⑮ / SlipHangTest 抓到。

#### ⑥ 调试渲染器：修掉 13950 条报错的真正原因 + 开关不再卡一下

另外加了一次**预热**（加载时先画一帧再隐藏），把首次上传网格/字形图集的成本
从"按开关那一刻"挪到加载时。

| 最慢单帧 | **84.59 ms**（开关那一刻） | **5.17 ms** |

## v0.5.1 — 相比 v0.5.0（固定起跳力度 / 三维调试渲染器 / 星球预设）

#### ① 跳跃：固定力度，不同星球不同高度（修正 v0.5.0 的建模错误）

v0.5.0 曾让「每颗星球都跳 0.75 m」—— 那是错的。人体起跳的**力度是固定的**，
换星球变的是高度：

```
设计目标 h = 0.75 m（地球上脚底板离地）
   ↓ 用**地球**重力反解
起跳速度 v = √(2·g_earth·h) − g_earth·dt/2 = 3.7536 m/s   ← 腿部冲量，跨星球不变
   ↓ 换星球只换 g
峰高 apex(g) = (m+1)·v·dt − g·dt²·m(m+1)/2,  m = ⌈v/(g·dt)⌉
```

| 星球 | g | v | 峰高 |
|---|---|---|---|
| 地球 | 9.80665 | 3.7536 | **0.750 m** |
| 月球 | 1.62 | 3.7536 | **4.380 m** |
| 火星 | 3.711 | 3.7536 | **1.929 m** |
| Apex 重力 | 20.7802 | 3.7536 | **0.370 m** |

有限加速时间 `JumpAccelTime` 现在**不改变力度**（出口速度恒等于 v），只把冲量分摊到
n 个 tick；总峰高会变大（蹬伸过程中人已经上升了一段，物理正确）。

#### ② 三维速度 / 加速度调试渲染器（新）

## v0.4.3 — 相比 v0.4.2（镜头摇晃重写为 ∞ / 物理合规审计）

需求方（m00459 / m00460）提的两条，逐条处理：

**① 镜头摇晃「像单脚跳」—— 根因是波形的周期性错误，不是幅度问题**

旧实现：`bobLat = cos(φ/2)`、`bobRoll = cos(φ/2)`，而相位 `φ` 按
`[0, 2π)` 回绕。**cos(φ/2) 的周期是 4π 而不是 2π**，所以每次回绕时横向位移与侧倾
从 −幅度**瞬间跳到** +幅度（跳幅 = 2×幅度），频率 = 每步一次（冲刺约 3 次/秒）。
竖直与点头用的是 `sin(φ)/cos(φ)`，反倒是连续的 —— 所以只有"左右歪"在跳，
玩家感受就是「镜头缓慢向左倾斜一点点，然后迅速回正」。

**新实现**（`core/BobWaveform.cs`）：相位改口径为**步幅相位**（2π = 左右各一步），

    lateral  = A_lat  · sin(φ)          ← 1 次 / 步幅
    vertical = A_vert · sin(2φ)         ← 2 次 / 步幅 = 一步一次
    pitch    = P      · sin(2φ)
    roll     = R      · sin(φ)

这正是 Gerono 双纽线 `(x, y) = (A sinφ, B sin 2φ)` —— 屏幕平面上一个横放的 **∞**，
处处光滑，**没有任何回绕跳变**。相位差必须是 0 不能 90°：90° 时
`cos2φ = 1 − 2sin²φ` ⇒ 轨迹退化成抛物线（y 对 x 单值，不可能自交）。

| 真实链路（core+rig，60 Hz）单 tick 横向最大变化 | — | 1.2578 mm（解析上界 1.7009 ×1.35 界内） |
| 频率 | 横向/侧倾 3.00 Hz（带每步跳变） | 竖直 **3.00 Hz**、横向 **1.50 Hz**（严格 2:1） |
| 幅度 | 不变 | 不变（垂直峰到峰 12.40 mm、点头 0.248°、侧倾 0.257°、侧摆 16.04 mm） |

删掉入口还不够 —— 原来空中像有虚拟平台的第二个来源是**落地那一 tick 的地面摩擦**：
落地 tick 只把状态写成 `Ground`，真正的地面推进要等下一 tick 的 `StepGround`，
而 `StepGround` 会**先吃一 tick 地面摩擦**（`Friction=4.0`，6.6 m/s 一次掉 ≈0.44 m/s）
才轮到滑铲触发。于是「蹲键不松 → 落地继续滑铲 → 还能再跳」这条需求只成立 3 次，

省掉那一 tick 的无谓摩擦。

还有第三个（更隐蔽的）入口：**离地那一 tick 的状态残留**。`UpdateGroundContact` 的

一 tick 的 `Slide`（本 tick 结束时已经是「离地 + Slide」），要等下一 tick 的 `StepSlide`
才被离地保险丝打回 `Air`。

**那一 tick 不是无害的**：下一 tick 的 `StepSlide` 一进门就被保险丝 `return` 掉，
于是整整**少积一次重力**。独立验证的逐 tick 实测：prev 在第 6 tick `vy` 恒 0、
`py` 不动；new 为 `vy = −0.34634 = −g·dt`、`py` 少 `0.005772 = g·dt²`；之后每 tick
累加 `g·dt²`，300 tick 的无跳滑出台沿轨迹累计到**位置差 0.2275 m / 速度差 5.5414 m/s**。
所以这是补回一个真实漏掉的重力 tick，不是"只改标签"的洁癖改动。
「滑铲跳」那条轨迹不受影响（每次离地都在跳跃 tick，`DoJump` 已先置 `Air`，
命中 `_justJumped` 早退分支；实测 420+485+40 tick 逐位相同）。
自检 1 断言「空中任何 tick 都不是 Slide」，并**自证**离地那一刻的状态确实是 Slide。

实测（`.re-apex/tools/apex_sim` 探针，8 连跳）：每跳进滑铲时水平速度
`10.16 → 6.60 → 6.45 → 6.29 → 6.14 → 9.79 → 6.60 → 6.45` —— 掉速只来自滑铲自身摩擦，
`SlideBoostCooldown = 2 s` 到期后 +3.81 把速度补回来，**链条可以无限持续**。

**跳跃疲劳是保留的，不是 bug**：wiki 明确 `antiMultiJumpHeightFrac = 0.30`、
落地后 0.150 s→0.75 s 线性恢复（`.re-apex/wiki/text0.txt:204-290`）。所以连续滑铲跳
第 0 跳满高（胶囊中心峰值 2.327 m）、后续约 30%（0.951 m）**是 Apex 忠实行为**。
越跳越高在结构上已经不可能：自检 5c 断言每跳起跳初速 ≤ `JumpVelocity`，
5d 断言胶囊中心峰值非递增，5e 断言只要在空中竖直速度每 tick 只减 `g·dt`。

**③ 倒退坠下高台被边缘吸住 —— 方向闸从速度扩到意图**

原有的 ④b 闸看的是**已经形成**的水平速度（`approach = -dot(水平速度, 墙面法线)`，
小于 `-WallGrabMaxRecedeSpeed(0.05)` 就拒绝）。它抓不到一个窗口：玩家从静止开始按 S，
速度要几 tick 才建立起背离墙面的分量，那几 tick 里 `approach ≈ 0`，仍然会被抓一下 ——
需求方描述的吸附住一小段时间正是这个。新增 ②b 闸：
`if (input.MoveZ < -0.3f) return false;` —— 按 S 就是我要往下掉，不是我要抓。

自检 9a/9b 用 approach 扫描把这条闸钉死：approach 从 −6 到 +1.5 每 0.125 一次，
分界精确落在 **approach = 0.000**（配置容差 0.05 之内），且面朝墙 + 纯垂直下落
仍然自动扒住（扒墙默认化没有回退）。

**④ 顺手修掉的三处会误导后来人的假代码 / 死代码**

- `ApexCameraRig.cs` 的 `gaitAirOk = s.OnGround || s.Gait.FlightFraction > 0.05f`：
  `UpdateBobPhase` 在非 Ground/Slide 状态一律把 speed 传 0，空中 `FlightFraction` 恒为 0，
  那个分支**永远为假**。已改成真实口径 `s.OnGround`（bob 只在脚踩地时存在）。
- HUD 只打真实步频（3.29 Hz），但相机实际用 `min(步频, BobCadenceMaxHz)` = 3.00 Hz 推相位，
  照着 HUD 会误判画面频率。HUD 已补 `cam=3.00Hz` 与实时摇晃倍率 `bob×`。
- `integration_test.gd` 的坡面滑铲用例**一直在测别的机制**：旧写法从坡顶平台冲刺 →
  按 Ctrl → 滑出边缘 → 落到坡面上继续滑。它依赖两条隐式条件才成立 ——
  ① 滑出台沿后落地那一刻仍在滑铲（v0.4.1 靠"空中滑铲"续住，而那正是要删的缺陷）；
  ② 落地速度够得着门槛（实测落地水平速度 **7.99 ≥ 5.08**，靠的是 9a「落地即滑铲」

  30° 的斜率从 **+1.9847 翻成 −0.5063**（符号都反了），15° 不受影响（窗口内脚底始终 >0.4 m）。

## v0.4.1 — 相比 v0.4（滑铲物理化 + 悬空卡死修复）

需求原话：「滑铲要按物理走（坡道越陡越快）」，以及一张「1.3 m 平台翻越时角色悬在半空、
W 按着也上不去」的截图。

**① 滑铲改成真实物理（`a = g·sinθ − μ·g·cosθ`）**

v0.4 及之前：滑铲用一条与坡度无关的 `SlideFriction = 0.9` 做指数衰减，
所以**下坡反而比平地减速更快**，与直觉完全相反。

v0.4.1 的解法（`ApexMovementCore.StepSlide`）：

```
a = g·sinθ − μ·g·cosθ          θ = 地面法线与 up 的夹角
v -= a·dt  （沿坡面切线方向）
```

- **平地**（θ=0）：`a = −μ·g`，匀减速 —— 与旧行为量级一致，手感不突变。
- **下坡**（θ>0）：`g·sinθ` 把速度往回加。θ 越大加速越猛 —— 这就是「坡越陡越快」。
- **临界角**：`tanθ = μ`，μ=0.45 ⇒ **24.23°**。比这更陡的坡上，滑铲**永远停不下来**
  （只受 `SlideMaxSpeed = 10.16 m/s` 封顶）。
- **上坡**（θ<0）：两项同向减速，滑铲很快被 `SlideMinSpeed = 2.5 m/s` 终止。

**② μ 按地面材质取（`IFrictionWorld`）**

需求原话：「保留这套公式，默认 0.45，摩擦系数改成可调的，便于游戏未来添加不同材质不同摩擦系数的地面」。

```csharp
public interface IFrictionWorld
{
    bool SampleFriction(F3 position, out float coefficient);   // 取不到就返回 false
}
```

- 求解器每次滑铲 tick 先问世界「脚下这块地 μ 是多少」，问不到才用 `SlideFrictionCoefficient = 0.45`。
- Godot 侧实现（`GodotMovementWorld.SampleFriction`）：沿 up 打一条 2 m 射线，
  从命中节点起沿父链逐级找 meta `friction`（float，最多 4 层）。
  **场地里加材质只是给 `StaticBody3D` 挂一个 meta，不用改求解器、不用重编译**。
- 测试场地新增三条材质带（`friction_lanes`）：冰 `0.05` / 常规 `0.45`（不挂 meta） / 粗糙 `0.90`。

**③ 不自动滑**（需求答复：「不自动，必须先蹲下滑铲」）
滑铲入口仍是 `Shift` 冲刺 + `Ctrl`，`BeginSlide` 前置条件没动。物理化只改了"进入之后怎么减速"。

**④ 修掉「1.3 m 平台翻越时悬空卡死」**

根因不在翻越逻辑，在碰撞桥接层的法线兜底：

```
GodotMovementWorld.QueryNormalAt(contactPos, r, hh, fallback)
  → GetRestInfo 在"扫掠停在接触面边缘"时打空（ProbeDepth 只有 2 cm，胶囊其实还没接触）
  → return fallback.Normalized()          ← fallback = -delta.Normalized()
```

于是法线变成「运动方向的反向」这种伪法线。`MoveWithCollision` 拿它做
`_vel = F3.ProjectOnPlane(_vel, normal)`，把**水平与竖直分量一起吃掉** ⇒
人悬在半空、`vy` 一路掉到 −41 而位置纹丝不动（实测轨迹：
`t=67 post vy=-0.000 vz=-0.000` 之后每 tick `post y` 恒定 1.8466）。

修法（`GodotMovementWorld.QueryNormalAt`）：`GetRestInfo` 打空时不再直接返回伪法线，而是两级兜底：

1. **原地把胶囊整体放大 `ProbeDepth`**（半径与两端半球同时外扩 2 cm，不位移）再查一次。
   保证与"刚刚接触的那个面"产生 2 cm 的重叠，从而拿到真法线；不位移所以法线仍是接触点的法线。
   典型场景（胶囊圆柱段贴着竖直墙面往上滑）走的就是这一级。
2. 仍取不到则退回**"竖直墙"启发式**：把 `-fallback` 投影到水平面再归一化，只挡水平分量。
   宁可当成墙（最差只是少走一点）也不要用 `-delta` 当法线（会把竖直速度一起抹掉、永久卡死）。

**⑤ 顺带修掉的分段攀爬**：到顶脱手不再被"反作弊黑名单"永久拉黑，高墙可以分多段爬上去
（根因与修法见 §7 的 ㉑）。

## v0.4 — 相比 v0.3（**自研手感，不再对标 Apex**）

需求原话：「从现在开始，不参照 apex 的移动系统，而是打造我们自己的移动系统」。
所以这一节不是"把 Apex 抄得更准"，而是**按需求方口径重写手感规则**，Apex 数值只当参考。

**① 镜头抖动：从"手拍常数"改成"步态模型推导"（需求 1）**

v0.3 的摇晃是拍出来的：`步频 = 1.2 + 速度 × 0.55` Hz、`幅度 = clamp(速度/5, 0, 1.4) × 26 mm`。
两个问题：① 频率与身高、步幅毫无关系，冲刺时算出 **4.83 Hz** —— 人类跑步步频上限约 3.3 Hz，
这个数字物理上不存在；② 幅度随速度线性堆到 73 mm 峰到峰，再乘 1.6 倍"冲刺加成"。

v0.4 换成一条**生物力学推导链**（`core/GaitModel.cs`，纯函数、可脱离引擎单测）：

```
身高 H ──0.53──▶ 腿长 L ──Froude 0.45──▶ 偏好步速 v_pref = 0.45·sqrt(g_earth·L)
     ──走跑切换 1.9·v_pref──▶ 步频 f(速度) ──L_stride = v/f──▶ 摆腿角 theta = asin(L_stride/2L)
     ──▶ 垂直起伏 = L(1−cos theta)·吸收系数 + 腾空弹道项 ──▶ 点头 / 侧倾
```

> 注意这里用**地球重力 9.81**，不是游戏重力 20.78 —— 腾空相时长要按真人跑步算，
> 游戏重力只负责"跳起来多高"。两者混用会让腾空比虚高一个量级。

| 速度 | 步态 | 步频 | 步幅 | 腾空比 | 垂直半幅（峰到峰） | 点头半幅 |
|---|---|---|---|---|---|---|
| 1.43 m/s（偏好步速） | 走 | 1.90 Hz | 0.75 m | 0 | 4.6 mm（9 mm） | 0.18° |
| 4.41 m/s（本插件行走） | 跑 | 2.99 Hz | 1.48 m | 0.165 | 3.7 mm（7 mm） | 0.15° |
| 6.60 m/s（本插件冲刺） | 跑 | 3.29 Hz | 2.01 m | 0.380 | 10.3 mm（21 mm） | 0.41° |

**奔跑腾空相**不是拍一个系数：`腾空比 = clamp01((v − v_runStart)/(v_sprint − v_runStart)) × 0.38`，
再由 `半腾空时长 = 腾空比 × 周期 / 2` 算弹道自由落体高度 `0.5·g·t²` —— 所以"跑得越快腾空越久、
起伏越大"是算出来的，不是调出来的。走路（腾空比 0）的起伏只来自摆腿压缩，所以走路比跑步**更稳**。

| 判据（需求方口径 m02752「舒适档」） | v0.3 实测 | v0.4 实测 | **v0.4.2 实测** |
|---|---|---|---|
| 垂直起伏峰到峰 ≤ **2.5 cm**（v0.4.2 收紧到 ≤1.5 cm） | 冲刺 73 mm（超 3 倍） | 冲刺 **21 mm** ✅ | 冲刺 **12.4 mm** ✅ |
| 点头半幅 ≤ **0.8°**（v0.4.2 改成峰到峰 ≤0.30°） | 冲刺 0.83°（且频率 4.83 Hz） | 冲刺 **0.41°** | 峰到峰 **0.248°** ✅ |
| 落地冲击 1.5–2.5° | 2.49°（v0.3 已收敛） | 2.49°（未改） ✅ | 2.49°（未改） ✅ |
| 频率是否物理可能（人类跑步 ≤3.3 Hz） | 4.83 Hz ❌ | **3.29 Hz** ✅ | 相机相位封顶 **3.00 Hz** ✅ |

实现要点：

| **(0.25, 1.0] m** | 小障碍 | 只按 `W` 撞住；**`W+Space` 直接翻越**（`Vault`，不触发攀爬）；翻越结束**快速恢复满速** | `TryVaultObstacle`（只在 `StepGround` 的跳跃分支调用）+ `_vaultExitSpeed = 意图速度 × 0.85` + 落地后 `VaultRecoverTime = 0.25 s` 内加速倍率 ×3 |
| **> 1.0 m** | 墙 | 撞上去停住；需要 `W+Space` 跳起后攀爬（攀爬时水平速度 = 0） | `TryAttachWallGrab`（`VaultMaxHeight` 以上才允许挂） |

> **v0.4 删掉了"自动翻越探测"**：v0.3 每 2 tick 从地面向前打一次射线，只要探到台面就自动翻 ——
> 于是"贴墙按 W 就爬墙 / 走过台面就自己翻"同时发生，玩家没法拒绝。现在翻越**只由 `W+Space` 触发**，
> `TraversalProbeCount` 恒为 0（属性保留只为兼容自检历史）。
>
> 顺带修掉 v0.3 留下的 **1.0–2.03 m 死区**：v0.3 的"太矮不挂"探针高度用 `AutoMantleMaxHeight`(2.03)，
> 于是 1–2 m 的墙既翻不过去（> `VaultMaxHeight`）又挂不住 —— 玩家撞上去干瞪眼。
> v0.4 探针改为**相对脚底** `VaultMaxHeight × 0.6`，2.5 m 墙能正常挂住（自检 ⑰b）。

## v0.3 — 相比 v0.2

**① 攀爬：从"被动吸入"改成"有条件的攀爬状态"（本轮主线）**

v0.2 的攀爬是"只要在空中按着 W 贴着墙就被吸上去，吸上就一股劲爬到顶再抛出去" ——
玩家没有任何拒绝的余地，贴墙跳一下就会被拽走。v0.3 把它改成**真正可进入 / 可退出**的状态：

| 项 | v0.2 | v0.3 |
|---|---|---|
| 触发条件 | 空中 + `MoveZ > 0.3`（按着 W 贴墙就吸） | **四条同时满足**：① 在空中（地面 / 滑铲不触发）② 面向墙，视角夹角 ≤ **45.57°** = arccos 0.7（wiki attach 容差）③ **朝墙速度 ≥ 0.5 m/s** ④ 同一面墙不重复附着（除非低于上次附着点，或新面与旧面夹角 ≥ 25.842°） |
| 吸附后 | 直接一路爬到顶 → End boost 抛出去 | **进入 `Climb` 状态**，竖直速度先归零（挂住，不自己上升） |
| 上爬 | 无条件 | **必须按住 `W`**：`ClimbSpeed` 2.0 m/s（78.7 hu/s），实测 0.5 s 正好 +1.000 m |
| 松手 | 无 | `ClimbNoInputGrace` **0.22 s** 后取消攀爬并下落（实测宽限 13 tick 内仍 Climb，超时转 Air，vy=-7.28）；侧向输入持续 1 s 也取消 |
| 到顶 | 统一 End boost | 有台面可挂 ⇒ **补爬 0.35 m 进入 `Hang`（扒墙）**，再按 `W` 上墙；无台面 ⇒ 保持 End boost 上抛 |
| 探测频率 | 每 tick 无条件 | `ClimbProbeInterval`（默认 1，可降到 2） |
| 爬墙真的会动吗 | **不会** —— `Step()` 在 Climb 分支提前 `return`，跳过位移步骤，v0.2 只赋速度不位移 | 会（运动学位移 + 每 tick 贴墙钳制） |

顺带把**翻越**也加了输入门槛：`TryTraversal` 现在要求 `MoveZ > 0.3`（wiki：mantle grab 需要
移动输入指向墙面）。原先站在墙边**完全不操作**也会被 6 m 墙翻上去。

**② 移动 tick 固定 60/s 基准，昂贵探测降到 30/s**

| 项 | v0.2 | v0.3 |
|---|---|---|
| tick 基准 | `SyncTickRateWithEngine()` 用 `Engine.PhysicsTicksPerSecond` 覆盖 `TickRate` | **固定 60/s**（`MovementConfig.PinnedTickRate`）；工程物理频率不是 60 时由 `ApexTickClock` 累加器折算 |
| 卡顿补帧 | 无上限 | 单帧最多补 **4** tick，其余丢弃并计入 `DroppedTicks` |
| 翻越探针 | 每 tick | `TraversalProbeInterval = 2`（60 Hz tick → 30 Hz 探针） |
| 攀爬探针 | 每 tick | `ClimbProbeInterval = 1`（可配） |

实测：30 fps 每帧消费 2 tick；144 fps 跑 10 秒（1440 帧）得 **599** tick，无累积漂移。

**③ 落地镜头晃动大幅收敛（对应需求"晃动过于剧烈"）**

| 项 | v0.2 | v0.3 |
|---|---|---|
| `LandingPitchImpulse` | `{0, 0.9, 2.2, 4.0, 6.5}` → 峰值 5.9° / 10.8° / 14.6°，后两档**全部撞上** `MaxKickAngle`(10.3°) ⇒ 所有大落地都是同一次 10° 甩头 | `{0, 0.25, 0.55, 0.90, 1.33}` → 峰值 **0.47° / 1.04° / 1.69° / 2.49°** |
| `MaxKickAngle` | 0.18 rad（10.3°，实际工作点） | **0.075 rad（4.3°），只作保险丝**（实测峰值 0.0435 < 0.075 × 0.9） |
| 走路 bob | 0.035 m / 0.022 m / 0.35° / 0.30° | 0.026 m / 0.016 m / 0.24° / 0.20°（实测移动峰值 0.0281 m） |
| `KickScale` | 无 | 新增总倍率（0 = 关掉所有视角踢；落地踢与手动踢都受它控制） |

**④ 打滑态 Slip（对应逆向字段 `slipSpeed` / `IsSlipping` / `m_slipAirRestrictTime` / `m_slipAirRestrictDirection`）**

新增 `MovementState.Slip` 与 `ISlipWorld` 探针接口：场景里放一个 `Node3D` 打滑体积
（`add_to_group("slip_volume")` + 子 `CollisionShape3D`），角色进入就被地面方向推着滑走。

| 项 | 行为 |
|---|---|
| 进入 | 探针命中打滑体积 ⇒ `Slip`。**只覆盖地面态**：蹲下优先转 `Slide`、按跳优先转 `Air`，环境不抢玩家状态 |
| 速度 | 沿体积方向加速到 `SlipSpeed`（默认 8 m/s，实测 8.00）；方向由体积给，没配方向时**从体积中心往外推**（对应 `C_TriggerSlipSphere` 的"站进去被挤出去"） |
| 方向限制 | 空中时用 `SlipAirRestrictConeDeg`（默认 35°）把速度压进以原方向为轴的圆锥，`m_slipAirRestrictTime` 计时结束后衰减到 0；纯数学部分 `ClampToCone` 已开放为 `public static` 供自检验证 |
| 垂直方向 | `LockToPlane` 只压掉**向上**分量（`if (upVel > 0f) _vel -= _up * upVel`），重力照常 ⇒ 空中进滑区会正常落地，**不会悬空**（这条是自检抓出来的真实 bug，见第 7 节） |
| 探测频率 | `SlipProbeInterval = 2` ⇒ 60 Hz tick 下 30 Hz 采样（实测 60 tick 只采样 30 次） |

**⑤ 独立扒墙 WallHang（对应逆向字段 `wallhang` / `m_wallHanging` / `IsWallHanging` / `automantle_disable_hang` / `ACT_MP_WALLHANG_*` / `sound_wallHang*`）**

v0.3 早先的 `Hang` 只是"攀爬到顶后的过渡态"。本轮新增真正独立的 `MovementState.WallHang`：

| 项 | 行为 |
|---|---|
| 触发 | **非强制**：空中 + 贴墙 + **按住蹲键**才挂（`automantle_disable_hang` 语义：能自动翻越的矮墙不挂）。松蹲立刻松手 |
| 姿态 | 速度恒为 0（`speed=0.00` / `vy=0.00`），身体贴到墙面（离墙 = 半径 + 皮肤，实测 z=-1.574） |
| 握力 | `WallHangGrip` 从 1.0 开始消耗（HUD `grip=`），耗尽自动脱手；按 `W` 上爬会回补（`m_wallDangleClimbProgressFloor` 语义，实测 0.81 → 0.90） |
| 移动 | 按 `W` 沿墙上爬 ≈1 m/s；按 `A`/`D` 横移 ≈0.8 m/s（`ACT_MP_WALLHANG_LEFT/RIGHT`）；不动则缓慢下滑（`sound_wallHangSlip`，实测 0.22 m） |
| 脱手 | 松蹲 / 握力耗尽 / 超 `WallHangMaxTime`(6 s) / 甩视角超过 `WallHangMaxViewAngle`(45.57°) / 按跳（蹬墙跳，实测 vz=2.69 vy=6.15） |
| 重复挂 | `_wallHangNeedRelease` 门闩：脱手后必须"离开墙面一次"才能再挂，否则按住蹲的玩家会在冷却一过被立刻抓回去，`m_wallHangTime` 永远走不到上限 |
| 探测频率 | 不按蹲时提前返回，**零射线开销**；按住蹲时每 tick 探（实测 40 tick 探 40 次） |

**⑥ v0.3 逆向补充（常量对齐）**

攀爬常量与 wiki 对齐：attach offset **100 hu**、climb 空间 cutoff **147 hu**、end boost **28 hu**、
attach 视角容差 **45.57°** = arccos(0.7)、可攀墙面角度 > **45.572°**。
